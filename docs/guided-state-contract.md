# Guided builder: initial state contract

Owner: Adhvay Iyer. Tracks [Frontend #4](https://github.com/GameMaker-CSP/Frontend/issues/4).
Audited against `b7b506f53` on 2026-10-05. This is a starter contract for teammate review.

## Inherited source of truth

`pages/game-maker.html` owns the live `game` object, `nextId`, and a separate
`a11y` object. Guided and advanced controls currently update those same objects.
The initial adapter must preserve this ownership rather than create another store.

| Source symbol | Contract |
| --- | --- |
| `game` | `title`, `playerName`, `playerEmoji`, `background`, `levels` |
| `emptyLevel()` | `playerStart: {x, y}`, `barriers`, `stars`, `npcs`, `hearts`, `startHearts` |
| `uid()` | Returns `nextId`, then increments it; preserve this counter when adapting a save. |
| `applyGameData(data)` | Copies `data.game` into the live game, restores a truthy `data.nextId`, selects level 0, updates controls, and records undo history. |
| `startPlay()` | Requires at least one level with a star, then starts the inherited preview. |

The page's inline level format is different from the code snippets generated by
`assets/js/GameEnginev1.2/builder/templates.js`; those snippets are not saved-game payloads.

## Save and restore boundary

The browser key is `uesl_gm_v2`. Its value is JSON containing this envelope:

```json
{
  "game": {
    "title": "Star Adventure",
    "playerName": "Hero",
    "playerEmoji": "🎮",
    "background": "dark",
    "levels": []
  },
  "nextId": 1
}
```

This empty-level example explains the format; it cannot be played until a level
with a star is added. Preserve actual levels, object IDs, and unknown fields.

`gmConfirmSave()` stores the envelope locally before trying an account save.
The account request is `POST /api/game/save` with
`{name, game_data: JSON.stringify(envelope)}`. `name` is the library label and can
differ from `game.title`. The backend upserts by authenticated user and label.
`GET /api/game/load/<id>` returns `game_data` as a JSON string, which the page
parses before calling `applyGameData`.

## First small adapter slice

1. Validate a requested title without changing the input: require text, trim its
   outer whitespace, reject an empty result, and enforce the existing input's
   40 UTF-16-unit `maxlength` (emoji can use two units).
2. Return field-specific corrections as `{field: 'title', code, message}`.
3. For valid input, return a new save envelope with only `game.title` changed.
   Preserve all other data. Invalid input must leave the original save intact.

The initial helper is a standalone prototype. Connecting it to Continue, Preview,
and Save is a later integration task with Rohan and Ishan.

`validateGameTitle(value)` is exported from
`assets/js/game-maker-guided/validation.js`. It returns
`{ok: true, value: trimmedTitle}` or `{ok: false, errors: [...]}`. Error codes are
`title_type`, `title_required`, and `title_too_long`; failures return no replacement title.
Run its checks with Node 22 or newer:

```bash
node --test tests/game-maker-guided/*.test.mjs
```

## Compatibility gaps to address later

- `a11y` is separate from `game` and is **not** in the current save envelope.
  Accessibility persistence needs an agreed, backward-compatible extension.
- `applyGameData` trusts the parsed structure and can partially change live state
  before a malformed save fails. A title adapter is not full save validation.
- Storage quota/access errors and automatic draft recovery still need handling.
- No format migration, storage replacement, or UI ownership change is introduced here.
